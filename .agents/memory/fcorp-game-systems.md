## Training System
- 37 training types across 7 categories: physical, technical, tactical, setpieces, psychological, recovery, game
- The HEAD COACH (AI) always decides the weekly plan — the owner only sets the coach's philosophy
- 6 philosophies: balanced, attacking, defensive, physical, technical, possession
- Weekly plan is generated by `generateWeeklyPlan()` in `src/lib/coachAI.ts`
- Plan stored in `fcorp_game_state` localStorage under `weeklyPlan` field

## Competition Names
- Real UEFA names: Лига чемпионов УЕФА / Лига Европы УЕФА / Лига конференций УЕФА
- No fictional "Еврокубок" — all real tournament names from `src/data/competitions.ts`
- Domestic cups mapped per country in `COUNTRY_CUPS` — some countries don't have a real League Cup (Spain, France, Netherlands) — use alternatives instead of fictional names
- UCL: top 1–2 direct, 3–4 qualifying; UEL: 5–7; UECL: 8–9 (UEFA only)
- Continental competitions gated behind Level 1 only

## Schedule Engine (src/lib/scheduleEngine.ts)
**Critical rule**: `dayOfWeek` is ALWAYS derived from the actual `Date` object inside `addMatch()` — never trust hardcoded day values from callers.
- League: Saturdays only (skip international breaks)
- UCL: specific Tuesday/Wednesday dates (hardcoded UEFA calendar dates for 2025-26)
- UEL/UECL: Thursdays
- Cups: dynamically generated actual Wednesdays via `generateCupWednesdays()` — NOT hardcoded day=10 dates
- Same-day conflict: `usedDates` Set prevents collisions; cup dates skipped if already taken by European matches

## Game State
- `src/lib/gameState.ts` — extends existing localStorage, VERSION=1
- Coach stored as `HeadCoach` under `fcorp_game_state` → `coach`
- Player states: fatigue/fitness/form/sharpness/morale per player
- Weekly plan cached by week number, regenerated if stale

**Why:** Decisions on Day 1 of implementation should be consistent. Future work on match engine, injury system, growth engine should use the types and storage patterns in gameState.ts.

**How to apply:** When adding new game systems, read gameState.ts first and extend the `GameState` interface rather than creating new localStorage keys.
